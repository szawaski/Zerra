# Repository Generation

| Approach | Direction | Use when |
|---|---|---|
| **Code First** | models → database | you write the models and Zerra creates and updates the schema |
| **Database First** | database → models | the database exists and Zerra writes the models |

## Code First

### 1. Define the Models

```csharp
[Entity("PetType")]
public sealed class PetTypeDataModel
{
    [Identity(true)]        // primary key, generated by the database
    public int Id { get; set; }

    [StoreProperties(64)]   // max length 64; not null because string isn't nullable
    public string Name { get; set; } = null!;
}

[Entity("Pet")]
public sealed class PetDataModel
{
    [Identity(true)]
    public int Id { get; set; }

    [StoreProperties(128)]
    public string Name { get; set; } = null!;

    public string? Nickname { get; set; }   // nullable column

    public int PetTypeId { get; set; }

    [Relation(nameof(PetTypeId))]           // foreign key
    public PetTypeDataModel? PetType { get; set; }
}
```

| Attribute | On | Does |
|---|---|---|
| `[Entity("Name")]` | class | names the table; the class name without it |
| `[Identity]` | property | the primary key; `true` when the database generates it |
| `[StoreProperties(...)]` | property | length, precision and scale, `NotNull`, `StoreTextEncoding.NonUnicode` (`varchar` instead of `nvarchar`), or `StoreDatePart.Date`. A column is NOT NULL when its member can't be null (`string`, `int`) and nullable when it can (`string?`, `int?`); without nullable annotations every reference type can |
| `[StoreName("Name")]` | property | names the column; letters, digits, and underscores |
| `[StoreExclude]` | property | no column, never read or saved |
| `[Relation("ForeignKey")]` | property | a related model or collection, linked by the named foreign key, or several in the order of the related identities |
| `[StoreIndex]`, `[StoreIndex("Name")]` | property | an index; members with the same name form one combined index. `Unique`, `Order`, `Descending`. Indexed strings and `byte[]` need a length |

### 2. Generate at Startup

```csharp
CodeFirstGeneration.Generate(engine, DataStoreGenerationType.CodeFirst, [typeof(PetTypeDataModel), typeof(PetDataModel)], log);
```

| `DataStoreGenerationType` | Does |
|---|---|
| `CodeFirst` | applies the changes |
| `Preview` | logs the plan without applying it |
| `NoCreate` | skips new tables and columns |
| `NoUpdate` | skips changes to existing ones |
| `NoDelete` | skips dropping removed tables, columns, and indexes |

Combine them, such as `CodeFirst | NoDelete` to add and change but never drop.

## Database First

`DatabaseFirstGeneration.Generate` reads the tables of a SQL Server, PostgreSQL, MySQL, or MariaDB database and writes a model class for each. Run it from a small console app or a test, and again when the database changes:

```csharp
var models = DatabaseFirstGeneration.Generate(new MsSqlEngine(connectionString), "MyProject.Domain.DataModels", "DataModel");
foreach (var model in models)
    File.WriteAllText(Path.Combine(@"..\MyProject.Domain\DataModels", model.FileName), model.Source);
```

Each model is a `partial` class in its own file, with the attributes Code First would need to build the same table:

```csharp
[Entity("Order")]
public partial class OrderDataModel
{
    [Identity(true)]
    public int ID { get; set; }

    public int CustomerID { get; set; }

    [StoreProperties(32)]
    public string Number { get; set; } = null!;

    public string? Notes { get; set; }

    [StoreProperties(18, 2)]
    public decimal Total { get; set; }

    [Relation(nameof(CustomerID))]
    public CustomerDataModel? Customer { get; set; }

    [Relation(nameof(OrderLineDataModel.OrderID))]
    public List<OrderLineDataModel>? OrderLines { get; set; }
}
```

- Keys, identities, composite keys, foreign keys (as relations both ways), and indexes named `IX_{Table}_...` come across. Running Code First on the result finds nothing to change.
- Add your own members in another file of the `partial` class, so regenerating doesn't overwrite them.
- Where a column doesn't fit exactly, a comment above the member says why, such as a SQL Server `money` column becoming `decimal(19, 4)`.
- PostgreSQL names come back lowercase unless they were created quoted.
- MongoDB, the in-memory engine, and the event stores have no schema to read, and throw `NotSupportedException`.

Register the generated models like any other, with a `TransactStoreProvider<TModel>` each ([Repository](Repository.md#setup)).
